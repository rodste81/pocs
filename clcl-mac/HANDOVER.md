## Objetivo

O usuário (Rodrigo) usava o **CLCL**, um clipboard manager antigo para Windows, e quer um equivalente para **macOS**.
Decisão tomada: **Electron + TypeScript**. Motivos: o usuário prefere JS, a UI sai rápido e o app também roda no Windows.

O primeiro pedido concreto é **pré-carregar os menus (templates) com os dados que ele já extraiu do banco antigo do CLCL**, que estão em:

```
/Users/rods/Library/Mobile Documents/com~apple~CloudDocs/Desktop/new clcl
```

Essa pasta só existe no Mac dele, e a sessão anterior rodava na nuvem sem acesso a ela. **Esse é o motivo do handover.**
O formato desses arquivos ainda é desconhecido (JSON? TXT? o `regist.dat` original?). Inspecione antes de escrever o importador.

## Plano para o Electron

Crie o projeto em `clcl-electron/`, sugestão: Electron + TypeScript + Vite (electron-vite ou Electron Forge).

| Função | Implementação |
|---|---|
| Ícone na barra de menus | `Tray` + `app.dock.hide()` |
| Atalhos globais (⌥C histórico+templates, ⌥T templates) | `globalShortcut` |
| Detectar cópia | Polling a cada ~300 ms comparando o conteúdo/hash (o macOS não notifica mudanças) |
| Ler/gravar formatos | `clipboard.availableFormats()`, `readText/readHTML/readRTF/readImage`, `readBuffer`/`writeBuffer` para tipos do Mac (ex.: `public.file-url`) |
| Ignorar senhas | Pular se `clipboard.has('org.nspasteboard.ConcealedType')` ou `TransientType` / `AutoGeneratedType` (testar) |
| Menu popup | `Menu.buildFromTemplate(...).popup()` na posição do mouse (`screen.getCursorScreenPoint()`). Rótulos `1. texto…` como no CLCL (`&%1d. %t`). Templates em submenus por pasta. Alternativa futura: janela sem borda com busca |
| Colar automático | `app.hide()` (devolve o foco ao app anterior) → aguardar ~100 ms → ⌘V via `osascript -e 'tell application "System Events" to keystroke "v" using command down'` ou `@nut-tree/nut-js`. Exige **Acessibilidade** em Ajustes do Sistema → Privacidade e Segurança. Shift segurado = só copiar |
| App ativo (ignorar apps) | Pacote `get-windows` ou `osascript` |
| Persistência | `better-sqlite3` ou JSON em `app.getPath('userData')` |
| Expandir `%d` / `%t` em templates | Ferramenta embutida (port do `tool_text`) |

Padrões do CLCL a manter:
- histórico de **30** itens;
- duplicata modo **1** (ignora se igual ao último item);
- **não recapturar** um template colado pelo próprio app;
- menu do ⌥C = histórico, separador, submenu "Templates", separador, Cancelar.

### Fase 1 sugerida (MVP)

1. Bandeja, polling, histórico persistente e dedupe.
2. **Importador dos dados de `new clcl`** → árvore de templates (pastas e itens) salva no storage do app.
3. ⌥C abre o menu com histórico + templates; ⌥T só templates.
4. Escolher um item copia e cola (⌘V); Shift = só copiar.
5. Item de menu "Limpar histórico", e "Sair" na bandeja.

### Importador do `regist.dat` (se o usuário tiver o arquivo original)

O formato está descrito em `DESIGN.md` §1.8, com o código de referência em `clcl-src/core-oficial-nakkag/File.c` (`file_file_to_item`, `file_item_to_file`):

- `\x04` título `\0` → início de pasta (filhos até `\x05`);
- `\x01` título `\0` data(hex 16) `\0` janela `\0` plugin_str `\0` plugin_param `\0` "mod,vk,paste" `\0` `\x02` → item;
- depois, por formato: tamanho `\0` nome do formato `\0` plugin_str `\0` plugin_param `\0` opção `\0` `\x03` + bytes;
- strings em Shift-JIS (versões antigas) ou UTF-16 (v2 Unicode). Confira os bytes antes de decidir.

Para texto, use o formato `UNICODE TEXT` (UTF-16LE) ou `TEXT` (CP932/Shift-JIS).
